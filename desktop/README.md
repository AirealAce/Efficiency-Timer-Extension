## Download setup (for users)

Use the publisher's **ReflectionTimer-3.12.8-win-x64.zip** release package, extract it, and run **ReflectionTimer.exe**. It includes .NET and the eight bundled MP3s; no separate audio download is needed. No SDK, Node, Python, Chrome extension, or administrator installation is required. **Guided setup → step 1 → Install on this PC** optionally installs per-user and creates Desktop/Start menu shortcuts; it backs up an existing install and retains the user's local MP3 library. Quit old copies from the tray before upgrading. The prepared package is Windows x64; other platforms are not verified. An unsigned release can trigger Windows reputation warnings; do not disable security settings or bypass organizational policy.

Read **[START-HERE.html](START-HERE.html)** from the extracted download for complete installation, credential, authorization, privacy, troubleshooting, update, and multi-PC instructions. Guided setup opens on first run and remains available at the top of Settings. It can generate a private setup script that binds the user's own spreadsheet and creates missing `Temp` / `test` tabs without changing existing tabs. Receiver **2.7.0** adds this editor-only setup helper; an existing **2.6.0** deployment still supports all timer/check-in features and does not need redeployment just to add a PC.

The private setup code includes the token in a readable encoded format, **not encryption**. Transfer it only between your own trusted PCs; never post it publicly. Other users should create their own connection. Timers, schedules and local drafts are per-PC; sharing a spreadsheet does not synchronize running sessions. Windows DPAPI state files are not a portable backup across PCs/profiles.

## Install and switch over

Requires Windows and the **.NET 10 Desktop Runtime (x64)**. Building requires the .NET 10 SDK and restores the pinned [NAudio 3.0.1](https://www.nuget.org/packages/NAudio/3.0.1) dependency for MP3 playback. Playback uses Windows audio codecs/output and works offline.

From PowerShell in this folder:

```powershell
.\install.ps1
# Or select a separately installed SDK:
.\install.ps1 -DotNet 'C:\path\to\dotnet.exe'
```

The installer runs tests, publishes a framework-dependent build, installs under `%LOCALAPPDATA%\Programs\ReflectionTimerDesktop`, and creates **Reflection Timer Desktop** on your desktop. Existing app binaries are copied to a dated backup before replacement. Close the app via **Quit**, not its window X, before updating. Neither installation nor updates erase saved data or enable Windows startup.

1. If needed, export a diagnostic report from the extension first. The desktop app can import its **future scheduled sessions** from that report under **Scheduling session times → Import extension schedules**. It does not automatically transfer an active countdown, browser settings, or pending reflection drafts; finish those first.
2. At `chrome://extensions`, turn off **Reflection Timer**. Leave it installed for rollback. Close any old webpage reflection overlays; if one lingers, refresh that page. The desktop app cannot toggle the extension itself.
3. Launch **Reflection Timer Desktop**, open **Settings**, and confirm the extension is off. This confirmation enables desktop timer starts and scheduled-session processing; it does not actually disable Chrome's copy.
4. Enter the same Google Sheet URL, deployed Apps Script URL ending in `/exec`, and Reflection API token used by the extension. **Save & test connection** is read-only. It neither creates a daily tab nor writes a reflection.
5. Leave the destination on automatic dates. Receiver 2.5.0 retains dated tabs, copies from the configured `Temp` template, alternating timestamp backgrounds, whole-row white entry borders, and full-width hour themes. Update the existing deployment for the new C–F fields and safe-retry protocol.
6. Optional: enable **Start in the tray when I sign in to Windows**. This affects only this app's per-user Windows startup entry. It is off by default.

## Using the app

- **Ctrl+Alt+`** (the backtick/tilde key on a US keyboard) starts an idle or finished timer immediately using the Timer page's current HH/MM/SS duration and options—even while editing a field, viewing another tab, or hidden in the tray. A paused timer resumes its remaining time unless you edited the duration, in which case a new session uses that duration, just like the Start/Resume button. Invalid values show an error instead of starting. The separate "Start timer at" appointment field and future schedules are unchanged. If the timer is already running, the shortcut ends it early and opens its normal reflection popup. This is not a test reflection and sends nothing until you save your message. Auto-start immediately begins the next full session if enabled and before its cutoff. The configured duration, audio options, and existing reflection drafts are preserved. Holding the shortcut does not repeatedly start/end sessions. Settings → Display → Keyboard shortcuts reports either shortcut's registration conflict independently.

- **App sound (x%)** is the same master-volume setting on Timer and above Success messages in Settings → Audio. Each event has a separate **Volume (x%)** slider immediately above its Fade out row, defaulting to 100% for existing configurations. Output is master × event volume (50% × 50% = 25%). These sliders autosave silently and update currently playing audio without restarting it. Muting an event does not interrupt other sounds. A scheduled session adopts its saved App sound level on start; all previews use the current master level. Volume changes leave timer duration/cutoff drafts and the unsaved default-threshold field intact.

- **Settings → Audio → Fade out after** appears beneath each of the four sound rows. Check it and choose how many seconds the sound plays before a one-second fade to silence. Each event saves independently and remembers its seconds when unchecked. Fade-out starts off for existing and new settings. Changes autosave silently and apply to the next playback, including custom MP3s, library sounds, and fallback audio. Session low-time sound overrides inherit the global low-time fade setting. Shorter tracks end normally; previews still stop after at most five seconds.
- Opening the Timer tab selects the first positive duration field from left to right, falling back to Hours if all are zero. Typing hours clears the untouched 15-minute preset; minutes you explicitly edit are preserved.
- Timer and Scheduling accept whole-number minutes and seconds above 59. Values carry into the next unit when you leave the duration editor, press Enter, or start/save the session: **1h 20m 100s → 1h 21m 40s**. Switching between Hours, Minutes, and Seconds keeps your typed values until you finish the group. The countdown previews the equivalent total while editing. The existing one-year total limit remains; oversized or invalid entries stay visible for correction rather than being silently clipped.
- **Ctrl+Alt+T** is a global shortcut that brings the running app's existing main window forward, including from the tray or a minimized state. It preserves the selected tab, maximized state, timer, and drafts; it does not start a session. On the Timer tab, it selects the first positive duration field from left to right, falling back to Hours if all are zero. An active modal dialog remains in front of its owner. The shortcut is released on Quit and does not launch a closed app. **Settings → Display → Keyboard shortcut** reports registration conflicts; close the conflicting app and reopen Reflection Timer to retry. It uses Windows' [RegisterHotKey API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) with repeat suppression, not a keyboard hook or keystroke logger.
- Start, pause/resume, reset, auto-start next session, and sound level are available on the regular timer.
- **Show floating timer** on Timer, **Settings → Display**, or the tray menu enables a compact always-on-top countdown with Start/Pause/Resume, shared HH/MM/SS fields, and Open app. The editors mirror the full timer immediately and are editable when stopped or paused; Enter starts/resumes the shared timer. **Ctrl+Alt+/** (the slash/question-mark key on a US keyboard) cycles **controls → time-only → hidden → controls**; **Ctrl+Alt+.** (period) returns directly to the controls. Showing controls selects the first positive duration field from left to right (Hours if all are zero). Running controls are read-only without changing the session. Shrinking leaves the visibility option checked, while hiding unchecks it. Closing its X or using Hide in the menu still hides the view directly. The window sizes to its contents and remembers visibility and dragged position across app closure and PC restart. **Settings → Display → Compact timer position** offers Remember dragged position, Center, Top left/right, Bottom left/right, Top center, and Bottom center. New installations built from this source default to Bottom left; saved placement preferences are retained. Dragging switches back to remembered custom placement. Saved positions are kept within a connected monitor's working area; presets use the compact window's current/saved monitor. This optional view is off by default.
- After completion without auto-start, both countdowns show zero for one second and then display the configured duration, ready for the next session. A paused timer still shows its remaining time, and automatically started or scheduled sessions display their new countdown immediately. This display change does not reset elapsed time or dismiss the reflection.
- **Start timer at**, above auto start on the Timer tab, queues a future session with **Schedule session** using the current duration, audio, volume, and auto-start options. With auto start unchecked it runs once. Scheduling leaves the current countdown alone; view, edit, or cancel the saved appointment in **Scheduling session times**. Enter a future local date/time as **MM/DD/YYYY hh:mm AM/PM**.
- **Enter** in the Timer tab's Hours, Minutes, or Seconds field normalizes the values and starts the timer with the current options (or resumes an unedited paused timer), just like **Start / Resume**. Invalid durations show the usual error without starting. Enter in Scheduling only normalizes the duration; it never starts a future appointment immediately.
- **Settings → Display → App theme** saves and immediately applies Dark, Light, High Contrast, or Glamour to every app window. Theme selection is independent of connection settings and does not upload anything.
- **Settings → Display → Reflection popup position** offers Center, Top left, Top right, Bottom left, and Bottom right (the default for new installations built from this source). Saved placement preferences are retained. Changes save immediately and apply when a regular, scheduled, or test reflection window opens. The popup uses the monitor containing the mouse pointer at opening, respects its taskbar working area and display scaling, and leaves a small corner margin. An already-open reflection does not move while you type. Close it with **Later**, then reopen **Pending reflections** to apply a new position without losing its draft.
- **Settings → Audio** configures four events: **Success** (Level Up), **Failure** (Out of Health), **Low on time** (Battle (Trainer)), and **Session end** (the unchanged original `popup.mp3`). Your existing custom session-end MP3 is retained on upgrade. Each picker offers **None** immediately below Default (or below the inherited-settings option on a session). None means silence, never a fallback. Select a library sound or a validated custom MP3 under 50 MB to automatically preview it; **Preview audio** replays it. Every preview lasts **at most five seconds**, including any fallback. A new preview replaces the previous preview even in Polite mode, without stopping unrelated audio unless its playback policy is Disruptive. Sound/mode selections autosave without a success chime; changing only the playback mode does not preview. Previews, messages, low-time warnings, and completion sounds all use the current App sound level multiplied by the event's volume. Previews never contact Sheets. Audio errors show a warning without recursively sounding Failure.
- Each event defaults to **Disruptive**, which cancels all earlier app audio before playing. **Polite** allows concurrent playback. **Assertive** plays at its configured level while lowering all other app voices to 25% of their configured levels; the most recent active Assertive voice has priority. Earlier Assertive voices recover in order, and original levels return when no Assertive sound remains. Muted events never interrupt other sounds. **Stop all app audio** cancels all voices; Quit does too. These policies never change other apps' audio or Windows volume. Concurrent voices are capped at 32 to protect output resources.
- Custom files stay at their original locations. Missing/unreadable files fall back to the event's local default, or the original extension sound if that library asset is absent. Public desktop packages contain no MP3 recordings. Local soundtrack support remains available; see `desktop/Sounds/README.md`. Actual session sounds play once through, not looped; battle tracks retain their full length. Only previews have the five-second limit. Paths are encrypted in saved state and removed from diagnostic exports, including timer/session overrides.
- **Low on time audio** is below **Disable auto-start at** on both Timer and Scheduling. It is checked by default for new timers and sessions; previously saved off choices stay off. **Settings → Audio → Default low-time warning** starts at 60 seconds and saves with the existing **Save settings** or **Save & test connection** button. Changing another audio option or switching tabs preserves an unsaved threshold edit. Each timer/session can follow this default or override its seconds-remaining threshold, and independently follow the global low-time sound or choose another library track/MP3. Playback behavior remains the global Low on time audio mode. Regular timer options save immediately; schedule options save with **Add session / Save changes**. Existing schedules retain their own settings.
- Low-time audio plays once per running session at or below its threshold. If the duration is already shorter than the threshold, it plays on the first live tick. Paused timers do not warn, finished timers do not play stale warnings after sleep, and a committed warning is not repeated by pause/resume or restart. Starting/resetting a session or beginning the next auto-start cycle rearms it. Changing a threshold or toggling the checkbox does not rearm an already-played warning. Pausing, resetting, starting a new regular session, or unchecking Low on time stops its current sound. Completion audio is emitted for a new reflection even while an earlier reflection remains open; reopening the same draft does not replay it.
- Each scheduled session has its own local start date/time (minute precision), duration, repeat option, and sound level. Up to 50 one-time appointments are retained. **Scheduling session times → When a scheduled session overlaps** defaults to ending the current session with a reflection, then starting the scheduled session. This also protects paused sessions. The new appointment uses its own duration and options.
- The overlap alternatives are **Ask me** and **Wait until the current session ends**. Ask leaves the current timer running while offering start-with-reflection, wait, or skip; closing that dialog chooses wait. Waiting sessions and unanswered choices survive restarts and appear in the schedule list. Waiting appointments run oldest first when the current session finishes, is ended early, or is reset, ahead of ordinary auto-start. Pausing does not cancel future appointments.
- After sleep or downtime, only the latest newly missed appointment is kept; earlier newly missed appointments are skipped, and future ones remain. Already waiting appointments are retained. Normal deadline completion keeps its reflection, and an unfinished session replaced by a scheduled appointment now keeps an early-end reflection with its actual elapsed time.
- Auto-start repeats the duration immediately after completion, independently of the reflection window. After a long sleep it resumes once, rather than generating a flood of missed sessions.
- **Disable auto-start at** sits below the auto-start option on both the Timer and scheduled-session forms. Checking it automatically enables auto-start. Enter a local cutoff date/time (minute precision); on the Timer, edits save when you leave the field or press Enter. The cutoff disables repeating, but lets the current session finish and show its reflection. It is an absolute, one-time cutoff that survives pause/resume, sleep, and app restarts, not a daily recurring rule. Unchecking the cutoff leaves auto-start on indefinitely; turning off auto-start also clears its cutoff.
- Each scheduled appointment has its own optional cutoff, which must be after its start. A cutoff does not cancel independent future appointments. If a missed appointment starts after its own cutoff, its initial session still runs once, with repeating disabled. Existing timers and schedules keep their current settings without a cutoff until you choose one.
- The window X hides the app to the tray. Double-click the tray icon to reopen it; right-click for pending reflections, an issue marker, or Quit. Quitting stops alerts until the app is opened again. Windows sleep, shutdown, lock-screen restrictions, and notification settings can delay alerts; this app does not wake a sleeping computer.
- A reflection is a separate Windows window, not injected into a webpage. Drafts save locally after a short pause while typing and on close. **Later** retains the draft. **Skip** discards that prompt. **Save & send** first commits locally and then attempts Sheets delivery. Ctrl+Enter saves.
- Early-end reflections show a smaller field beneath the reflection with placeholder **Reason for ending early**. It is optional, limited to 1,000 characters, and saved with the reflection draft. Ctrl+Alt+backtick and scheduled replacements preserve the original session's actual/allotted time. Completed sessions leave E/F blank.
- **Test reflection prompt** always sends to the existing tab named **test**, never `Temp`, `Template`, or a dated tab. The receiver reports an error if `test` is missing.

## Local saves and delivery

The encrypted outbox retains the local date, UTC offset, destination, and content from the moment you save, even if delivery happens later. Entries that have not been attempted send automatically when the connection is configured and available.

Receiver 2.5.0 advertises the `request-id-v1` protocol. Before an entry's first attempt, the desktop checks that capability and pins the entry to its original receiver URL. Protected network failures, timeouts, HTTP 429, and server errors retry automatically, retaining the same ID, contents, timing, and destination. Delays grow from 15 seconds to a five-minute maximum; after eight failed attempts the entry needs review. A protected interrupted upload can resume safely after restarting. Older/unprotected attempted entries are never silently upgraded or automatically retried, and a changed receiver or lost protocol support requires review.

The receiver reserves each ID under its write lock before touching cells. Repeated identical requests return the original success; reusing an ID for different contents is rejected. Completed receipts are cached in Script Properties (up to 500) and retained in timestamp-cell notes for older-entry lookup. Preserve those notes and `RT_RECEIPT_` properties. Unresolved reservations are never automatically pruned. This is not an atomic transaction across Google services: an interrupted partial write is deliberately held as **NeedsReview**, rather than risk inserting a duplicate.

For a held entry, inspect the Sheet, then choose **Already in Sheet** or **Retry selected**. Retrying a partial-write/ID-conflict entry explicitly assigns a new ID after the warning; do this only when you have confirmed another insertion is appropriate. Other manual retries retain the ID. A maximum of 200 previously sent entries is retained locally; unsent entries are never automatically pruned. Concurrent uploads are serialized.

An old backup can contain stale state, so recovery pauses timers, disables scheduled-session processing until reconfirmed, and holds unsent entries for review. Review future schedules and pending prompts too: an older backup may contain a prompt you already handled. An unreadable original is preserved for recovery. If neither state file can be read, the app refuses startup rather than resetting your data.

Data lives in `%LOCALAPPDATA%\ReflectionTimerDesktop`:

- `state.dat`: timer, schedules, connection, drafts, and outbox, encrypted with Windows DPAPI for the current Windows user.
- `state.dat.bak`: previous committed encrypted snapshot. Writes use a flushed temporary file and atomic replacement.
- `diagnostics.dat`: encrypted rolling activity metadata, plus a previous-write backup.

Encryption protects stored files at rest; it is not protection against malware running as your Windows account. Keep the Windows profile/DPAPI keys when backing up; these files alone are not a portable cross-account backup. Data is not stored in the repository or desktop shortcut. The app does not read Chrome profile files. Do not share the data files or connection token in a public issue.

## Debugging

Click **Mark issue** when something feels wrong, then **Diagnostics → Export diagnostic report**. Reports include timer actions, app focus, schedules, prompts, upload outcomes, resume/session events, and issue markers. They exclude reflection text, drafts, connection credentials, browsing URLs, window titles, and other-app activity. Timestamps, scheduled sessions, and entry IDs are still personal metadata; review before sharing. Nothing uploads diagnostics automatically.

The rolling log retains at most 1,200 events / 7 days and can be paused or cleared. Retention is enforced during recording/reporting; disk files update on a successful log write. Clearing replaces the current log; the previous encrypted backup can still contain older events. Logs are best effort and can have gaps during crashes or storage failure.
